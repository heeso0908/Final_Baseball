# TEX 2025 분석 챗봇 — 기술 문서

## 개요

Texas Rangers 2025 시즌의 부진(81승 81패, 잔차 -9.06승)을 다각도로 분석하는
대화형 AI 에이전트. **반사실 시뮬레이션**(이 시나리오였다면 몇 승?), 경쟁팀 통계 비교,
게임로그 조회, 10개년 historical 검색을 하나의 챗봇 인터페이스에서 제공한다.

분석 성격은 **오답노트(counterfactual)**. 인과추론(DML)이 아니므로 "X를 올리면
Y승 늘어난다" 식의 단정은 하지 않는다. 인과 분석은 별도 `causal_analysis.ipynb` 참고.

## 도구 상세

### 1. `simulate_scenario(sigmas: dict[str, float]) -> dict`

σ(표준편차 배율) 단위 조정으로 즉석 시뮬. 양수=개선, 음수=악화로 통일
(lower-better 피처도 양수=개선).

**입력 예시**
```python
{'K9': 0.3, 'BB9': 0.4, 'sv_pct': 0.5}
```

**조정 가능 피처** (15개)
- 불펜·접전: `sv_pct`, `SV_pg`, `onerun_wp`, `xi_wp`, `ir_pct`
- 투구: `K9`, `BB9`, `HR9`, `WHIP`, `k_bb`, `era_fip_diff`, `babip_against`, `go_ao`
- 기타: `home_away_diff`, `sb_pct`

**조정 비권장** (`pyth_W` 채널 중복)
- `ERA`, `OPS`, `rs_per_g`

**반환**
```python
{
    'predicted_W': 87.4,
    'delta': 1.2,                # 베이스라인 대비 잔차 변화
    'baseline_W': 86.2,
    'baseline_residual': -3.94,
    'adjustments': {
        'K9': {'sigma': 0.3, 'delta_raw': 0.227, 'new_value': 8.61},
        ...
    },
    'warnings': []
}
```

### 2. `lookup_pareto(name: str) -> dict`

v5 노트북 실행 시 캐시된 시나리오 결과 즉시 반환 (시뮬 호출 없음).

**Pareto 시나리오 3종** (`Final/output/pareto_summary.csv`)
| 이름 | alias | 설명 |
|---|---|---|
| `aggressive` / `공격적` | 최대 잔차 개선 | delta 최대화 |
| `balanced` / `균형점` / `topsis` | TOPSIS | 개선↑ + 불확실성↓ |
| `conservative` / `보수적` | 최소 불확실성 | std 최소화 |

**Grid 시나리오 6종** (`Final/output/signed_proxy_scenario_summary.csv`)
- `best_overall`, `best_bullpen`, `best_closegame`, `best_pitching`,
  `worst_overall`, `baseline`

---

### 3. `compare_team_2025(team: str) -> dict`

같은 시즌(2025) 두 팀의 투수 핵심 지표 비교. 한국어 별명 지원
(매리너스→SEA, 애슬래틱스→ATH, 휴스턴→HOU 등).

**비교 지표 10종**
- `ERA`, `FIP`, `K/9`, `BB/9`, `HR/9`
- `SV`, `BS`
- `BABIP`, `GB%`, `Hard%`

각 지표는 `{TEX, 대상팀, TEX-대상팀}` 형태로 반환. 양수 = TEX가 더 큼.

---

### 4. `swap_team_pitching(team: str) -> dict`

대상 팀의 K/9·BB/9·HR/9·BABIP를 σ 단위로 변환해 TEX 베이스라인에 이식.
"TEX가 SEA 수준 선발진이었다면 몇 승?" 류 질문 전용.

**변환 로직** (`tools.py:swap_team_pitching`)
```
sigma_raw = (target_value - tex_value) / feature_std
# higher-better (K/9): sigma = sigma_raw
# lower-better (BB/9, HR/9, BABIP): sigma = -sigma_raw
# (대상팀이 더 크면 = TEX 이식 시 악화)
```

이후 `simulate_scenario(sigmas)` 호출. 결과에 `caveat` 필드로
"통계만 swap한 ceiling 추정 — 라인업/구장/부상 효과 미반영" 명시.

---

### 5. `query_gamelog(month, opponent, home_only, away_only, one_run_only, extra_innings_only) -> dict`

`texas_2025_game_log.csv`(162경기)에서 조건 매칭 경기 집계.

**필터** (모두 optional)
- `month`: 1~12
- `opponent`: 팀 코드/별명
- `home_only` / `away_only`: bool
- `one_run_only`: 1점차 경기만
- `extra_innings_only`: 연장전만

**반환**: 매칭 수, W/L, 승률, 평균 득실, 득실 합계.

---

### 6. `query_team_history(year_from, year_to, residual_min, residual_max, team, top_n) -> dict`

`mlb_team_seasons.csv`(330행, 2015~2025)에서 historical 매칭.

**용도**
- "역대 잔차 -9승 수준 팀이 있었어?"
- "TEX 역대 잔차 추이는?"
- "2020년대 잔차 +5승 이상 팀은?"

**반환**: 매칭 수, 평균 잔차, 잔차 오름차순 상위 N개 팀-시즌.

## ML 잔차 엔진 (simulation_core.py)

### 학습 데이터
- `mlb_team_seasons.csv` 중 2015~2019 + 2021~2024 (2020 제외, 2025 제외)
- 약 270행, 18개 피처

### 모델 구성 (앙상블 평균)
| 모델 | 입력 스케일 | 하이퍼파라미터 |
|---|---|---|
| Ridge | StandardScaler | RidgeCV `alphas=[0.1, 1, 10, 100]` |
| Lasso | StandardScaler | LassoCV `alphas=[0.001, 0.01, 0.1, 1]` |
| RandomForest | 원본 | `n_estimators=300, min_samples_leaf=5` |
| XGBoost | 원본 | `n_estimators=100, lr=0.03, depth=2` |

> **v5 노트북과 차이**: 노트북은 GroupKFold(year)로 alpha 탐색,
> 본 모듈은 RidgeCV/LassoCV의 내장 KFold 사용. 결과 magnitude가 작을 수 있음
> (노트북 best delta +4.28 → 모듈 ~+1.2). 방향성은 일치하므로 챗봇용으로 충분.
> 정확 재현 필요 시 GroupKFold 로직 동기화.

### 캐싱 전략
- Streamlit `@st.cache_resource`로 Agent 인스턴스 1회 생성
- 모듈 레벨 `_state` dict에 학습된 모델·scaler·baseline 캐시
- 첫 import 약 10초, 이후 호출은 ms 단위

### `_sigma_to_delta` 부호 규칙
```python
LOWER_BETTER = {'ir_pct', 'HR9', 'BB9', 'WHIP', 'babip_against', 'era_fip_diff'}
sign = -1 if feature in LOWER_BETTER else +1
delta = sign * sigma * feat_std[feature]
```

이로써 사용자는 항상 **양수=개선**으로 일관되게 사고 가능.

## 한계 및 주의사항

### 모델 한계
- 베이스라인 잔차 예측 -3.94 vs 실제 -9.06 (절반만 잡음)
- ML이 평균 회귀 → 극단값(연쇄 부상 시즌)은 과소예측
- 시뮬 magnitude는 보수적 (방향성은 정확)

### 데이터 한계
- 시즌 단위 통계만 사용 (월별·매치업 단위 미반영)
- 라인업·구장·부상 타임라인은 베이스라인 통계에 흡수되어 있음
- "이식 시뮬"은 통계 swap만 — ceiling 추정으로 해석

### 챗봇 거동
- LLM이 도구 호출 안 하고 직접 추측해 답할 수 있음 → system_prompt 6장의
  "도구 호출 없이 시뮬 수치 추측 금지" 규칙으로 억제
- 멀티턴 히스토리는 `agent_history`로 유지하되, 메모리 부담 시 새 세션 권장
- 한국어 별명이 다 매핑돼있지 않음 → `tools.py:_TEAM_ALIAS` 추가 필요 시 확장
